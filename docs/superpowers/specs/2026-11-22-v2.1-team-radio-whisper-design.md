## 1. Executive Summary & Goals

### Problem
F1 telemetry dashboards typically show numbers, lap charts, and speed traces, but miss the dramatic human dimension: real-time voice communications between driver and race engineer. In pivotal moments (e.g., Carlos Sainz's tactical DRS-train masterclass in Singapore 2023, or George Russell's dramatic final-lap heartbreak), strategy decisions are negotiated vocally over radio before appearing in timing sheets.

### Goal
Deliver a production-grade, immersive **AI Team Radio Cockpit** within Mission Control and Live Mode:
1. **Real Audio Streaming**: Stream real team radio MP3 audio recordings directly from `livetiming.formula1.com` via OpenF1 `/v1/team_radio`.
2. **Interactive Audio Waveform Visualizer**: 60fps HTML5 Canvas spectrum analyzer powered by Web Audio API `AnalyserNode`, complete with scrub bar, playback rate selector, and volume controls.
3. **Pit-Wall Bandpass Filter Simulation**: Interactive toggle applying real-time Biquad audio filtering ($300\,\text{Hz} - 3.4\,\text{kHz}$) to faithfully reproduce the acoustic characteristics of F1 helmet intercoms.
4. **Whisper Transcription & Tactical NLP**: Verbatim transcripts combined with strategic categorization (`tyre_issue`, `strategy_request`, `engine_issue`, `brake_issue`, `traffic`, `weather`), urgency rating ($1 - 5$), speaker identification (Driver vs Engineer), and key quote highlights.
5. **Live Race Sync & Popups**: Automatic dispatch of radio notification pills synced to the live race clock and broadcast delay slider.
6. **Zero-Network Resilience**: Guaranteed offline capability through curated JSON fixtures (`backend/data/fixtures/team_radio_singapore_2023.json`) and synthetic Web Audio oscillator fallbacks.

## 3. Data Models & Schemas

### 3.1 Backend Pydantic Schemas (`backend/app/schemas/radio.py`)

```python
from typing import Literal
from pydantic import BaseModel, Field

RadioClassification = Literal[
    "tyre_issue",
    "brake_issue",
    "engine_issue",
    "traffic",
    "weather",
    "strategy_request",
    "none",
]

RadioUrgency = Literal[1, 2, 3, 4, 5]  # 1: Routine / Calm -> 5: Critical / Race-altering

RadioSpeaker = Literal["driver", "race_engineer", "unknown"]

class RadioMessageItem(BaseModel):
    id: str = Field(..., description="Unique deterministic hash of session + driver + timestamp")
    meeting_key: int = Field(default=1219, description="Grand Prix meeting key")
    session_key: int = Field(default=9165, description="Session key (e.g. 9165 for Singapore 2023 Race)")
    driver_number: int = Field(..., description="Driver racing number (e.g. 55, 4, 63, 44, 1)")
    driver_code: str = Field(..., description="3-letter driver code (SAI, NOR, RUS, HAM, VER)")
    team_name: str = Field(..., description="Constructor name for livery tinting (Ferrari, McLaren...)")
    timestamp_utc: str = Field(..., description="ISO 8601 UTC broadcast timestamp")
    lap_number: int | None = Field(default=None, description="Race lap number at time of broadcast")
    recording_url: str = Field(..., description="MP3 audio stream URL from livetiming.formula1.com")
    duration_seconds: float = Field(default=3.5, description="Audio length in seconds")
    transcript: str = Field(..., description="Verbatim speech-to-text transcript")
    classification: RadioClassification = Field(default="none")
    urgency: RadioUrgency = Field(default=2)
    speaker: RadioSpeaker = Field(default="driver")
    trigger_phrase: str = Field(default="", description="Verbatim snippet triggering classification")

class RadioFeedResponse(BaseModel):
    status: Literal["success", "fixture_fallback", "error"]
    total_messages: int
    session_name: str
    circuit_name: str
    items: list[RadioMessageItem]
```

### 3.2 Frontend TypeScript DTOs (`frontend/src/types/radio.ts`)

Mirroring the backend response models and supplementing with UI state:
- `RadioMessage`: id, meetingKey, sessionKey, driverNumber, driverCode, teamName, teamColor, timestampUtc, lapNumber, recordingUrl, durationSeconds, transcript, classification, urgency, speaker, triggerPhrase.
- `RadioFilterState`: driverFilter (string | null), classificationFilter (RadioClassification | null), searchKeyword (string).
- `RadioPlaybackState`: isPlaying (boolean), currentTime (number), duration (number), isPitWallFilter (boolean), playbackRate (number), volume (number), isMuted (boolean).

### 4.1 Browser Autoplay Policy & User Gesture Handling
Modern browsers (Safari, Chrome) suspend `AudioContext` until a direct user gesture occurs.
`useTeamRadio` explicitly handles this:
- On user click of the "Play" button, `if (audioContext.state === "suspended") await audioContext.resume();`.
- If an external MP3 fails to load (due to strict CORS headers in certain headless browser runners or offline environments), `useTeamRadio` automatically falls back to an internal Web Audio oscillator synthesizing authentic F1 telemetry carrier tones and radio beeps, ensuring zero audio player crashes.

## 6. Frontend 4-File Ergonomics & Strict 529 Standards

### 6.1 The 4-File Layout
1. `frontend/src/types/radio.ts` — Clean TypeScript interfaces.
2. `frontend/src/services/radioApi.ts` — Native fetch implementation asserting response status and structured errors.
3. `frontend/src/hooks/useTeamRadio.ts` — Manages Web Audio context, HTMLAudioElement bindings, frequency analysis loop, filter toggles, and playlist indexing.
4. `frontend/src/components/mission-control/TeamRadioCockpit.tsx` — Root component coordinating sub-components.

### 6.2 Strict Rules Enforcement
- **STRICT BAN ON RAW UNICODE EMOJIS**: Vector icons exclusively from `lucide-react`: `Radio`, `Play`, `Pause`, `Volume2`, `VolumeX`, `Sliders`, `Gauge`, `Flame`, `ShieldAlert`, `Sparkles`, `Clock`, `Activity`, `CheckCircle2`.
- **Kiosk Ergonomics**: All interactive elements (play/pause toggle, seek bar, driver pills, category tabs, filter toggles) adhere to $\ge 44\text{px} \times 44\text{px}$ touch bounding boxes.
- **3 UI States**: Skeleton loading, structured Error state with retry action, Empty state when filter produces no results.
- **Zero Horizontal Overflow**: Verified across Desktop ($1440\text{px}$), Tablet ($834\text{px}$), and Mobile ($390\text{px}$).
