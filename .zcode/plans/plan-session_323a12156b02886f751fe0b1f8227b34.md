Mặc định theo khuyến nghị (user chưa chọn): RAG trước, corpus gitignored, Sporting 2024–2026, SignalR + fallback. Mỗi workstream là issue + thin-slice PR riêng theo quy trình 529 (branch từ develop, self-QA, E2E 3 viewport, Conventional Commits).

## Workstream 1 — Đại tu RAG FIA (làm trước, pain point lớn nhất)

**Slice 1: Fetch + parse PDF chính thức**
- `backend/scripts/fetch_fia_regs.py`: tải PDF từ fia.com/regulation/category/110 — 2026 Section A+B (Iss mới nhất), 2025 Sporting Iss 5, 2024 Sporting Iss 7. Idempotent theo filename pattern `fia_<season>...iss_<N>_<date>.pdf`, lưu `backend/data/fia_pdfs/` (gitignored). Header User-Agent chuẩn theo pillar resilient-networking.
- `backend/tools/fia_reg_parser.py`: pdfplumber → chunk theo cấu trúc điều luật. Mỗi chunk: `{doc, season, section, issue_date, article, heading, text (VERBATIM)}`. Xuất JSONL `backend/data/fia_regs/*.jsonl` (gitignored — bản quyền FIA). Make target `make fia-regs`.

**Slice 2: Hybrid retriever theo điều luật**
- Nâng `knowledge_retriever.py`: index gồm (a) article chunks verbatim — chính, (b) 36 curated notes giữ làm context phụ (flag `source: curated`).
- Exact-match số điều: regex query `art(icle)? 33.4` / `48.12` → boost thẳng chunk đúng điều.
- Hybrid: BM25 trên chunk (title+heading+text) + article-exact boost; citation object thêm `{article, doc, season, issue_date, verbatim}`; `/knowledge/note/{id}` trả toàn văn điều; chip ReferencesPanel hiển thị dạng "SR 2026 · Art 55.4" + popover verbatim + link PDF gốc FIA.
- Truy xuất mặc định theo mùa của race đang phân tích (year đã có trong analyze flow), fallback mùa gần nhất.

**Slice 3: Eval vàng**
- `backend/evals/knowledge_golden.json`: 30–40 Q tiếng Anh → article id kỳ vọng (pit lane speed, SC unlapping, track limits, parc fermé, penalty hệ số, restart…). Script đo recall@3; chạy local + pre-commit (corpus gitignored nên CI chỉ chạy khi có data); guard theo pattern rag-corpus-change hiện có.

## Workstream 2 — Live timing miễn phí (SignalR + fallback)

**Slice 1: Backend service**
- `backend/tools/live_timing.py`: asyncio task trong FastAPI lifespan dùng `fastf1.livetiming.client.SignalRClient` (có sẵn trong venv). Topics: TimingData, Position, WeatherData, RaceControlMessages, SessionInfo, SessionData, TopThree, TrackStatus, TeamRadio.
- Retry/backoff + header chuẩn; ring buffer in-memory + snapshot `backend/data/live/<session_key>/`. Feature flag `LIVE_TIMING_ENABLED` (mặc định off) — chống rủi ro 403/protocol change đã xảy ra 5/2025.
- API: `GET /live/session`, `GET /live/timing` (tower snapshot), `GET /live/stream` (SSE — frontend đã có pattern SSE từ useAnalyzeStream).
- Fallback: SignalR fail → `is_live=false`, dùng FastF1 on-demand như hiện tại (replay OpenF1 free sau session +30 phút nếu cần).

**Slice 2: Frontend**
- `hooks/useLiveTiming.ts` (EventSource) + component `LeaderboardTower`: pos/gap/interval/tyre compound/pit/DRS-cờ, màu team, 3 states skeleton/error/empty, không emoji (lucide), mobile xếp chồng. Hiện ở cột phải mission-control khi có session live + pill "LIVE" ở MissionHeader.

## Workstream 3 — Hero landing dùng số liệu thật
- Mở rộng `backend/scripts/prebake.py`: tính lap-delta curve THẬT cho 3 matchup hero từ FastF1 cache (chọn race thật, vd VER vs HAM 2024) → ghi `frontend/public/hero-matchups.json` (cùng cơ chế demo-race.json, commit được vì là số liệu dẫn xuất thống kê).
- LandingHero đọc JSON server-side; khi thiếu file fallback mảng hiện tại nhưng gắn nhãn "Illustrative". Radio snippet giữ curated (là quote flavor).

## Workstream 4 — Multi-driver pace grid
- `POST /pace-grid` (year, event, session, drivers[] tối đa 4): lap times N tay đua từ FastF1, fail-closed envelope theo pattern hiện có.
- `PaceComparisonChart` (SVG tự viết theo pattern TelemetryChart): N line theo màu team + sector split; đặt telemetry mode; 1v1 lap-delta giữ nguyên không đụng.
